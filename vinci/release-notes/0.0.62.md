Vinci Code 0.0.62 keeps your own provider keys away from Vinci's search service and counts more shell commands as file writes.

**Web search keeps other providers' keys to that provider.** In 0.0.61 and some earlier versions, when you used a model from another provider with your own API key and web search could not get results from Brave, Vinci Code sent that key to the Vinci search service. Web search now uses the Vinci search service only with a Vinci model. With another provider, if Brave is not set up or returns nothing, web search asks you to sign in to Vinci (`/login vinci`) or set `BRAVE_SEARCH_API_KEY`. Update to 0.0.62.

**More shell writes are sent to the file editor.** Vinci already blocks shell commands that write files and points the assistant to its file editor. It now also catches writes that come after a wrapper word such as `exec`, `env`, `sudo`, `nohup` or `xargs`, writes inside text handed to `sh -c`, `bash -c` or `eval`, and more redirect forms, such as `1>`, `>& file`, a `>` after `2>&1`, and writes inside `$(...)` or backticks. A command that only redirects error output, such as `2> file`, is treated as before.

**Network approval for a database status command.** The exemption that lets one read-only database status command skip the network approval ask now applies only when it is the whole command. A command that does more than that status check asks for network approval as usual. See [GHSA-7qjc-rmx4-5qvx](https://github.com/getsimpledirect/vinci-code-cli/security/advisories/GHSA-7qjc-rmx4-5qvx).

**"Always allow" is saved only when the command is allowed.** If Vinci refuses a command, choosing "Always allow this exact command" no longer saves a grant. The notice now says Vinci will remember the command if it passes the remaining checks.

**Secret masking in json and RPC output.** With secret masking on, `--mode json` and `--mode rpc` now mask what the terminal view already masked: a secret split across streamed lines, text with terminal escape sequences or carriage returns inside it, and more RPC fields such as edit patches and transcript responses. A built-in tool call that is cut off or interrupted no longer shows part of an argument value, in the final events or in the transcript. Because of this, streamed text, thinking and tool-argument bodies now arrive when each block or result ends, not piece by piece.

**Results from crew helpers start a new request.** When a crew helper's result is delivered back to the conversation, Vinci now treats it as a new request, so steps and a recovery block left over from the previous request no longer carry into it.

**The macOS sandbox protects more of the way to your protected files.** A link on the way to a protected file, such as a shell startup file, is now protected even when it sits in a folder you own that is currently read-only. The sandbox also refuses renaming or removing the folders above those links, including a project folder that holds part of that path; creating and editing files inside those folders stays allowed. Linux is unchanged: the destinations of such links stay protected there, but the links themselves are not yet protected.

Known limit: secret masking does not yet check text encoded with the URL-safe base64 alphabet (`-` and `_`) (#207).
