One fix, about an unattended run telling the truth about how it ended.

**A run the harness stopped can no longer report itself as done.** When Vinci's own guards halted a task mid-way — the no-progress latch, the action reserve, the per-turn ceiling, a refused checkpoint — the final outcome record could still say `DONE`, and a remote verification pass could paint it green on top. Those stops are now recorded per task and the outcome becomes `BLOCKED` with the stop's own words; nothing downstream can promote it. In unattended `-p` runs, where no one is there to answer "wait for the user's next instruction", the latch says so instead of asking, and the local `git add`/`git commit` that *is* the deliverable is no longer counted against the reserve or the ceiling — while `git push`, `gh`, and every editor, rewrite, or empty-commit option stay refused.

This is the harness half of the Vinci Worker Wave 0 fixes; the daemon half shipped separately with the worker.
