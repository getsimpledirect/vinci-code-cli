Vinci Code 0.0.64 lets you keep a session away from the web: when you say the session must stay offline, the web tools are refused for the rest of the session, unless you allow the web again.

**An offline scope for the web tools.** When your own message says the session must stay offline (for example "no online access" or "do not use the web"), or Vinci is started with `--offline`, the four web tools (`web_search`, `web_fetch`, `web_answer` and `library_docs`) are refused for the rest of the session. Crew helpers started in that session inherit the scope. Text inside attached files is not meant to set or end the scope (see the limits below); only what you type does. A later message of yours that allows the web again ("you may use the web now") ends the scope, unless it is limited ("... only for library docs") or sits inside quotes, inline code or a code block. Model calls are not affected: the scope covers the web tools only, not every network call.

Known limits: the scope is found from phrases, so some wordings are missed.
- A restriction is not detected when it is split by a comma ("Fix the app, do not use the web."), split by a file tag, worded as a paraphrase, or follows a product word and a line break.
- A hand-typed `<file ...>` opening tag with double-quoted or no attributes, placed before an attachment, can hide a restriction typed between it and the end of the attachment.
- A permission to use the web can still end the scope when it sits inside quotes or inline code that spans lines, after a stray quote mark, or when its limit uses a word Vinci does not recognize.
- Some attachment text is read as if you typed it: the rest of a file after a `</file>` inside its text (#257), and an attachment whose path contains `<file` or `</file`. A restriction written there sets the scope, and a permission written there can end it.
- The scope is one value per Vinci process: if the web tools are registered a second time in the same process, the scope is cleared.

This release also tightens the tests and the build check for `vinci report-wrong`; the command's behaviour is unchanged.
