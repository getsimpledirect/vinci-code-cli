One fix, and it is the reason this release exists.

**0.0.51 did not start.** Every launch of 0.0.51 failed immediately with `Cannot find package '@getsimpledirect/vinci-contracts'`. That package is private to us and is deliberately left out of what we ship; 0.0.51 pulled a value from it at startup anyway, so the moment the CLI loaded it stopped. Nothing you did caused it, and nothing on your machine needs cleaning up: 0.0.52 removes the dependency, and the vocabulary that was coming from that package is now built into Vinci Code itself.

**The release pipeline now proves the packaged CLI loads.** The check that let 0.0.51 through only asked the packaged binary for its version, which never loads the parts that failed. Releases now have to run the real launcher, with every extension and the agent loop, from the exact archive that ships — offline, against a local stand-in for the Vinci service — and get an answer back before anything is published. A build with 0.0.51's fault in it cannot pass that step; we confirmed it fails against the 0.0.51 archive and passes against this one.

If your install is stuck on 0.0.51, run `vinci` again: the updater will pick up 0.0.52. If it does not, `curl -fsSL https://vinci.getsimpledirect.com/install | sh` reinstalls cleanly.
