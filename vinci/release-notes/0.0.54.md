This release makes startup, permission review, and verification messages clearer.

**Blocked checks stay blocked.** When the sandbox cannot start a requested check and you ask Vinci to stop, its honest blocked report is preserved without another recovery attempt. Negative statements such as "No checks passed" and "No verification succeeded" no longer look like successful verification. Actual success claims still need supporting evidence.

**Small terminals keep the command in view before approval.** Long permission context is paged before affirmative choices appear, resizing starts review again, and No remains the default. Controls, literal backslashes, and Unicode characters are shown as unambiguous ASCII escapes in the review; the command itself is unchanged. The footer also keeps complete context metrics visible while shortening long project paths or model names.

**Getting started gives more useful guidance.** Invalid or missing `--mode` values are rejected before provider startup. Missing-credential messages follow the provider you selected, and `--list-models` can show the managed model catalog before login. Sign-in guidance explains the browser device-login flow and the terminal text prompt.

**Permission failures explain what is known.** Recognizable sandbox startup errors receive guidance about the required sandbox environment. Other permission failures stay qualified, with the original error preserved; Vinci does not recommend disabling confinement. Diagnostic paths are classified relative to the project, so a parent folder's name does not turn an ordinary project file into a scratch diagnostic.

**Undo explains shell-only steps.** `/undo` now says when a step contains shell changes it cannot restore, and gives a conditional hint about earlier file changes. It still consumes checkpoints in their existing order and does not claim to reverse shell commands.
