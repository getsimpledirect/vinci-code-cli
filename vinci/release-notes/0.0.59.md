Vinci Code 0.0.59 makes stops easier to understand and to recover from, and changes one exit code that scripts can rely on.

**Stops say which limit was reached.** When Vinci stops a turn because it reached its action or lookup limit, the message names the limit. In the interactive terminal it also says that typing continue picks the same task up in a fresh turn.

**In the interactive terminal, continue starts a fresh turn.** Typing continue after a limit stop starts a new turn on the same task with a new action budget. A continue typed while Vinci is still working, or sent over RPC, keeps the current budget.

**Declining an unrequested commit no longer adds a blocker.** If Vinci asks to stage or commit changes you did not ask for and you decline, it does not make the change, and the decline by itself no longer marks the task blocked; the task's outcome comes from its own checks. Vinci does not ask a second time in the same turn.

**Sandbox refusals are recorded and explained.** A check the sandbox refuses is saved as blocked. If the sandbox fails at startup, Vinci tells you what to check before retrying. Shortcut hints at startup and in the shortcut list no longer show keys that are not bound.

**Scripts: a refused required write now exits with code 3.** In print (-p) and JSON mode, a run whose required write was refused now exits with code 3 instead of 0, even when it ends without asking you anything.

**Some chained checks now point you to the direct command.** For one narrow kind of chained shell check, Vinci first stops and names the equivalent direct command to run instead. Repeating the same check a third time in a row runs it. After the first few of these stops, further ones count toward the turn's action limit.
