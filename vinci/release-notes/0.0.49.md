> **Why 0.0.49 and not 0.0.48?** A `vinci-v0.0.48` tag was pushed against the wrong commit — a
> worktree collision meant `git checkout vinci` failed while the tag command still ran. The release
> workflow refused it: the tag claimed 0.0.48 while the commit's identity said 0.0.47, so nothing
> was built, signed or uploaded. Release tags are immutable by repository rule, so 0.0.48 stays as
> an auditable failed mistag rather than being quietly reused.

## You no longer need a Vinci account

Install Vinci Code, run it, and use it — with your own Anthropic, OpenAI, Google, Groq or
OpenRouter key. There is nothing to sign up for and nothing to configure first.

```
/login      pick a provider
/model      pick a model
```

Vinci's own model classes are still offered first, so if you want us to handle inference,
billing and syncing, signing in is one keystroke away. It is simply no longer the price of
entry. Everything that makes Vinci Code worth using — the command guard, secret redaction,
receipts, checkpoints, review — works identically either way.

Prefer the previous behaviour, where only Vinci's own model classes are offered? Set
`VINCI_SHOW_OTHER_PROVIDERS=0`. That restricts provider and model CHOICE — it is not a network
kill switch, and does not stop the documented update check or first-run tool download.

## Your provider key never reaches us

In direct mode your key is stored on your machine, by the same file the underlying agent
already uses (`~/.pi/agent/auth.json`). Vinci Code adds no second credential store, and your
prompts go straight from your machine to the provider you chose — our servers are not in the
path at all. `vinci/PRIVACY.md` documents exactly what differs between the two modes, and names
the file that implements each claim so you can check rather than take our word.

## More kinds of key stay hidden when you share your screen

Secret redaction now recognises Groq, OpenRouter and Hugging Face keys, alongside the twenty
formats it already covered. These are precisely the providers bring-your-own-key invites, and
`/feedback` and `/issue` send transcripts off your machine — so a key shape the masker did not
know was a real hole.

The first version of these patterns matched only the exact key length each provider issues
today. A key one character longer passed through in clear, and every test still went green.
They now match by prefix and a minimum length, and the tests deliberately feed longer, shorter
and differently-cased keys.

## Security fixes

Four vulnerabilities in dependencies that ship to you, including the HTTP client and the
command parser the safety guard relies on: `undici`, `shell-quote`, `brace-expansion` and
`protobufjs`. The guard's command classification was re-verified after the parser change —
`rm -rf` and `git reset --hard` are still caught.

Vinci Code also now scans its own staged changes for credentials before every commit.

## Smaller things

- The `[Extension issues]` panel no longer warns that `/copy` conflicts with a built-in. It
  never actually did — Vinci's richer `/copy` was registered correctly all along, and only the
  warning disagreed.
- The model picker shows a provider badge on every entry, so a mixed list is never ambiguous.
  Your own provider's models show their exact id; Vinci's show their friendly name.
- A model you pick in direct mode is remembered between sessions.
