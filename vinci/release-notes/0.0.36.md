## Copying is easier

`/copy` puts Vinci's last message, the last code block, or the last command output on your
clipboard. No selecting text in your terminal, no worrying about whether your terminal copies on
select. `Alt+C` opens the same picker from the keyboard.

Your terminal's own text selection still works exactly as before — Vinci deliberately doesn't take
it over.

## Vinci remembers better, and forgets nothing quietly

Vinci keeps durable facts about your project in `.vinci/memory.md`. Two things changed:

- **It no longer silently forgets your oldest notes.** Previously only the most recent stretch of
  that file was used, so your earliest and often most important notes fell out with no indication.
  Now the important ones are kept, and when anything is left out Vinci is told so it can go read the
  file itself.
- **Vinci can add notes on its own** as it learns how your project works, instead of only when you
  say "remember this". Nothing is added secretly: each one shows a single line telling you what was
  saved, it's marked in the file as Vinci's own rather than yours, and `/memory` lets you delete any
  note. Your own edits to that file — headings, notes to yourself — are preserved.

## Report a bug without leaving the terminal

`/issue` opens a bug report or feature request on the public tracker, with the details already
filled in. Vinci doesn't post it: your browser opens with the form ready, you read it and press
Submit. Your conversation is never attached.

`/feedback` still exists for private feedback that goes only to us.

## Background agents

- **A helper that crashes no longer loses its work.** If an agent's process died partway through, its
  changes used to be discarded. They're now kept and offered to you for review.
- **Vinci asks which agent you meant.** If several are running and you say "message that agent",
  you get a short list to pick from instead of Vinci guessing.

## Vinci notices changes it didn't make itself

Vinci used to track what it had changed only through its own file editor. Anything done another way —
a `sed` command, a formatter, a code generator, a script — was invisible to it. That mattered most
right after a check passed: Vinci could tell you the work was verified while the files had moved on
underneath it.

It now looks at the working tree itself, so a change made any way at all is noticed and an earlier
"verified" is retired honestly.

## Verification you can act on

- **Vinci tells you what it actually checked.** When a check ran and passed, the closing message now
  says so and names the command, instead of leaving you to guess whether anything was run.
- **It says plainly when a check did not finish.** A run that could not complete its checks now
  closes with what is still owed — "the behavioural test suite has not been run, so this is not full
  verification" — rather than a bare claim.

## The file list at the end is the file list you changed

- **Work you asked Vinci to commit still appears.** Committing in the same turn used to leave the
  summary empty, exactly when the most had happened.
- **Vinci's own build leftovers no longer pad it.** Files produced by a compile or a test run — an
  `a.out`, a `.pyc` — are no longer counted as changes you made.
- **Files created outside the editor are counted.** A file written by a script or a generator now
  shows up like any other.

## Smaller things

- Questions where several answers are true at once now show a checklist you tick, rather than
  forcing a single choice.
- Agent rows no longer show raw token counts.
- Updates repair themselves. An install whose updater had fallen behind now repairs it on the next
  launch, so later fixes reach you without a reinstall.
- `/support` opens correctly instead of failing silently on some setups.
