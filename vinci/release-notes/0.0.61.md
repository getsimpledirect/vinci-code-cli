Vinci Code 0.0.61 makes file-write protection stricter and keeps a turn going through a brief connection error.

**File writes: stricter checks.** When `echo`, `printf`, `tee` or `cat` write a file with the `>|`, `&>` or `&>>` redirects, the write now goes to Vinci's file editor, as it already did for `>`. Vinci now decides whether a shell write lands inside your project from the path the operating system will actually write to, following symbolic links, so a path that passes through a link is judged by where the bytes land. On macOS, the sandbox also protects the links on the way to protected files, such as credentials and shell startup files, that you could otherwise replace.

**Clearer guidance when a shell write is blocked.** Vinci now tells the assistant where it can write: the file editor can create or change files in your project folder, and a file outside it needs your approval. The blocked file is named only when Vinci is certain which file it is. Sessions no longer read the block as "results cannot be saved".

**Connection retries no longer stop the run.** When a connection error is followed by a successful retry, the receipt no longer records a stop while the retry is pending, so unattended runs keep going. If every retry fails, the receipt says how many tries were made and that typing continue resumes. If you type while a retry is waiting, the retry is cancelled; when that leaves the request unfinished, the receipt says your input cancelled the retry.

**Fewer needless retries.** Digits such as 503 inside an id, a timestamp or a token count no longer count as an HTTP status, so those errors are not retried for that reason alone.
