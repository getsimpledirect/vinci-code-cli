Vinci Code 0.0.63 keeps recognized credentials out of notes saved with `remember` and `vinci report-wrong`, and makes three changes to pause, verification and action-limit behaviour.

**Memory notes refuse credentials.** The `remember` tool no longer saves a note that contains a recognized credential. It says why without repeating the note, and it may also refuse ordinary text that looks like a credential. When `remember` or `/memory` saves or forgets a note, the memory file is set to owner-only permissions. A memory path that is a symbolic link is refused. Other ways of writing a memory file, such as editing it directly, are unchanged.

**Problem reports mask credentials.** `vinci report-wrong` now masks recognized credentials in the note before saving it to the session file. Text that is not recognized as a credential is saved as typed, up to the first 500 characters. If masking cannot load, the command prints an error and exits without touching the session file.

**Failing read-only commands no longer count toward the failed-edit limit.** Failing read-only shell commands, such as `git status` outside a git repository, used to count toward the limit for failed edits, so the next edit was refused. They now have their own limit: after four of them, the next read-only command is paused ("Vinci paused after several failed read-only commands.") and edits stay allowed. A command Vinci does not recognize as read-only still counts toward the edit limit.

**A failed required check is not shown as verified.** When a narrower check passes but the required check failed, the receipt now says "Partially verified: required check `<command>` failed" (or "not run" if the required check was not rerun after a code change). After the receipt is written, the plan shows "Plan steps done — partially verified" instead of "Plan complete". When the required check has failed, Vinci no longer accepts a narrower rerun as completion evidence and asks for the failure to be fixed or reported.

**The action limit is named as such.** When a turn reaches its 25-action limit, the call that was blocked is now told that the limit was reached, with a hint to type `continue` in the interactive view, instead of being told it repeated an action. Other limit blocks still use the repeated-action wording.

Known limit: encoded secrets written in the URL-safe base64 alphabet (`-` and `_`) may not be masked; known token formats are not affected (#207).
