This release makes helper-result recovery and terminal status clearer while preserving the text you submit.

**Crew results respect your draft.** A finished helper no longer starts a new turn while you have unsent text or an open dialog. After reopening an interrupted conversation, queued results join the next submitted prompt instead of racing startup. Results already recorded in the conversation are not delivered again after a crash.

**Vero follows the task state.** The welcome header now pairs Vero artwork with readable working, review, waiting, blocked, and completion labels. The state label distinguishes checking, waiting for a decision, and unverified work; the task receipt remains the evidence for completion. Plain and reduced-motion modes retain readable status, and the header shows the same Vinci product version as the CLI.

**Ordinary prompts keep their spacing.** Leading spaces, indentation, blank lines, and trailing whitespace survive image-attachment handling when no image path needs replacing. Attaching an image tidies spacing beside its marker without flattening the surrounding text.

**Project paths keep their meaning.** The header and wide-terminal footer use `~` only for your home directory and paths inside it. A sibling such as `HOME-other/project` is no longer presented as a home-relative path. Narrow footers retain the project-name view.

**Read-only assessments preserve failed checks.** An explicit request to assess without editing keeps a failing check visible instead of turning the assessment into a repair. Independent reviews also receive the recorded result of a scoped formatting check when it prints nothing; that result cannot clear a failed behavioral test.

**Local Work commands have an explicit boundary.** `vinci runtime --help` exposes a separately configured local task client for inspecting state, replay, receipts, and selected artifacts; answering questions; approving or correcting an exact reviewed action; and requesting cancellation. It uses the selected local Work credential. Cancellation reports the request without promising that a worker or remote computation has stopped.
